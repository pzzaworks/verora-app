The `@verora/sdk` package wraps the contracts and the Verora API. It is built on
[viem](https://viem.sh): you bring a public client (and a wallet client for writes), and pass the
deployment manifest of the network you target. The public network is Ethereum Sepolia (chain 11155111).

## Install

```package-install
npm install @verora/sdk viem
```

`viem` is a peer dependency. The package ships ESM and CommonJS builds with type definitions.

## Quick start: requesters

Send a paid query to an agent and read its answer. Save the network's manifest from
[Deployments](/docs/reference/deployments) as `deployments/11155111.json` first.

```typescript title="ask.ts"
import { createPublicClient, createWalletClient, http, parseEther, type Hex } from 'viem';
import { privateKeyToAccount } from 'viem/accounts';
import { sepolia } from 'viem/chains';
import { VeroraClient, decodeText, encodeText, parseDeployment } from '@verora/sdk';
import manifest from './deployments/11155111.json';

// Load the key from a secrets manager or the environment; never commit it
const account = privateKeyToAccount(process.env.REQUESTER_KEY as Hex);
const contracts = parseDeployment(manifest);

const client = new VeroraClient({
  publicClient: createPublicClient({ chain: sepolia, transport: http(process.env.RPC_URL) }),
  walletClient: createWalletClient({ account, chain: sepolia, transport: http(process.env.RPC_URL) }),
  contracts,
  apiUrl: 'https://api.veroraprotocol.com',
});

// Pick the best-rated active agent from the indexer
const { data: agents } = await client.api.listAgents({ status: 'active', sort: 'reputation', limit: 1 });
if (agents.length === 0) throw new Error('No active agents');

const { queryId } = await client.createQuery({
  queryType: 'plaintext',
  queryData: encodeText('What is the ETH price?'),
  agents: [agents[0].id],
  payment: parseEther('0.001'),
});

const { responses } = await client.waitForQuery(queryId);
for (const response of responses) console.log(decodeText(response.responseData));
```

To keep the prompt and answer private, use [`createEncryptedQuery`](#send-an-encrypted-query) instead.

## Quick start: agent builders

An agent is an HTTPS endpoint the oracle POSTs queries to. It answers with response bytes signed by the
agent owner's key. Register the agent in the app at [/agents/register](/agents/register) (or with the
SDK, see [Running an Agent](/docs/guides/running-an-agent)), then run a server like this:

```typescript title="agent.ts"
import express from 'express';
import { createPublicClient, http, type Hex } from 'viem';
import { privateKeyToAccount } from 'viem/accounts';
import { sepolia } from 'viem/chains';
import {
  AgentProtocolError,
  decodeText,
  decryptQuery,
  encodeText,
  encryptResponse,
  fromBase64,
  parseAgentQueryRequest,
  parseDeployment,
  signAgentResponse,
  verifyAgentQueryRequest,
} from '@verora/sdk';
import manifest from './deployments/11155111.json';

// Load both secrets from your secrets manager; never commit them
const owner = privateKeyToAccount(process.env.AGENT_OWNER_KEY as Hex);
const encryptionSecretKey = fromBase64(process.env.AGENT_ENCRYPTION_SECRET_KEY ?? '');
const publicClient = createPublicClient({ chain: sepolia, transport: http(process.env.RPC_URL) });
const contracts = parseDeployment(manifest);

async function answer(prompt: string): Promise<string> {
  // Call your model here
  return `You asked: ${prompt}`;
}

const app = express();
app.use(express.json({ limit: '64kb' }));

app.get('/health', (_req, res) => {
  res.json({ status: 'healthy' });
});

app.post('/query', async (req, res) => {
  try {
    const request = parseAgentQueryRequest(req.body);
    // Check the request against the chain before doing any work or signing anything
    await verifyAgentQueryRequest(publicClient, contracts, request);

    let responseData: Hex;
    if (request.queryType === 'encrypted') {
      const { prompt, replyPublicKey } = decryptQuery(request.queryData, encryptionSecretKey);
      responseData = encryptResponse(await answer(prompt), replyPublicKey);
    } else {
      responseData = encodeText(await answer(decodeText(request.queryData)));
    }

    res.json(await signAgentResponse({ signer: owner, request, responseData }));
  } catch (error) {
    // Protocol errors (including AgentRequestRejectedError) are safe to echo back
    if (error instanceof AgentProtocolError) {
      res.status(400).json({ error: error.message });
      return;
    }
    // Log the details server-side; never leak internals to callers
    console.error('Failed to answer query', error);
    res.status(500).json({ error: 'Failed to answer' });
  }
});

app.listen(8080);
```

<Callout title="Always verify before signing" type="warn">
  Your endpoint is public, so anyone can POST a request to it, not just the Verora oracle.
  `verifyAgentQueryRequest(publicClient, contracts, request)` checks the request against the
  `QueryConsumer` contract on the chain you configured and throws if it does not match a real, open query
  assigned to your agent. Without it, an attacker could send a forged request and get your owner key to
  sign an answer to a query you never saw, which they could then submit on-chain in your agent's name.
</Callout>

## Create a client

<Steps>
  <Step>
    ### Load the deployment manifest

    The deploy script writes `verora-contracts/deployments/<chainId>.json`. There are deliberately no
    built-in addresses: `parseDeployment` validates the manifest and returns checksummed addresses.

    ```typescript
    import { parseDeployment } from '@verora/sdk';
    import manifest from './deployments/11155111.json';

    const contracts = parseDeployment(manifest);
    ```
  </Step>
  <Step>
    ### Construct the client

    <Tabs items={['Browser wallet', 'Node.js']}>
      <Tab value="Browser wallet">
        ```typescript
        import { createPublicClient, createWalletClient, custom, http } from 'viem';
        import { sepolia } from 'viem/chains';
        import { VeroraClient } from '@verora/sdk';

        const [account] = await window.ethereum.request({ method: 'eth_requestAccounts' });
        const publicClient = createPublicClient({ chain: sepolia, transport: http() });
        const walletClient = createWalletClient({ account, chain: sepolia, transport: custom(window.ethereum) });

        const client = new VeroraClient({
          publicClient,
          walletClient,
          contracts,
          apiUrl: 'https://api.veroraprotocol.com',
        });
        ```
      </Tab>
      <Tab value="Node.js">
        ```typescript
        import { createPublicClient, createWalletClient, http, type Hex } from 'viem';
        import { privateKeyToAccount } from 'viem/accounts';
        import { sepolia } from 'viem/chains';
        import { VeroraClient } from '@verora/sdk';

        // Load the key from a secrets manager or the environment; never commit it
        const account = privateKeyToAccount(process.env.REQUESTER_KEY as Hex);
        const publicClient = createPublicClient({ chain: sepolia, transport: http(process.env.RPC_URL) });
        const walletClient = createWalletClient({ account, chain: sepolia, transport: http(process.env.RPC_URL) });

        const client = new VeroraClient({
          publicClient,
          walletClient,
          contracts,
          apiUrl: 'https://api.veroraprotocol.com',
        });
        ```
      </Tab>
    </Tabs>

    `walletClient` is only required for writes, and `apiUrl` only for `client.api`. A read-only client
    needs just `publicClient` and `contracts`. `createVeroraClient(config)` is an equivalent factory. The
    snippets below reuse `client`, `publicClient`, `walletClient`, `account`, and `contracts` from here.
  </Step>
</Steps>

## Find agents

The REST API serves indexed agents with metadata, reputation, stake, and health:

```typescript
const { data: agents, total } = await client.api.listAgents({
  status: 'active',
  capability: 'price_feed',
  sort: 'reputation', // or 'stake' | 'newest'
  limit: 20,
});

const agent = await client.api.getAgent(agents[0].id);
console.log(agent.metadata?.name, agent.reputation / 100, '%', agent.healthStatus);
```

You can also read an agent straight from the chain. `client.getAgent(agentId)` returns the registry
record plus `status` and `reputation`.

## Send a plaintext query

```typescript
import { decodeText, encodeText } from '@verora/sdk';
import { parseEther } from 'viem';

const { queryId, receipt } = await client.createQuery({
  queryType: 'plaintext',
  queryData: encodeText('What is the ETH price?'),
  agents: [agentId],
  payment: parseEther('0.001'),
  ttlSeconds: 600, // default 10 minutes; min minQueryDuration + 60 s, max 30 days
});

const { query, responses, aggregatedResult } = await client.waitForQuery(queryId, {
  timeoutMs: 5 * 60_000, // default
  pollIntervalMs: 3000, // default
});

for (const response of responses) {
  console.log(response.agentId, decodeText(response.responseData));
}
```

`createQuery` reads the latest block and sets the deadline to `block.timestamp + ttlSeconds`. The
contract requires every query to stay open for at least `minQueryDuration` (5 minutes by default, read
it with `client.getMinQueryDuration()`), so `ttlSeconds` must be a whole number of at least
`minQueryDuration + DEADLINE_INCLUSION_BUFFER_SECONDS` (60 seconds of headroom for the transaction to
land) and at most 30 days. Anything else throws `InvalidArgumentError` before a transaction is sent.

The payment is split equally between the responders the oracle accepts. `waitForQuery` polls until the query is `Completed`
or `Failed` and throws `QueryTimeoutError` if it is neither when the timeout elapses.

## Send an encrypted query

Encrypted queries keep both the prompt and the answer unreadable on-chain. Your key pair is derived from
a wallet signature, so nothing secret is stored and answers stay readable after reloads.

```typescript
import { deriveEncryptionKeyPair } from '@verora/sdk';
import { parseEther } from 'viem';

// Derived from a wallet signature: nothing secret is stored
const keyPair = await deriveEncryptionKeyPair((message) => walletClient.signMessage({ account, message }));

const agent = await client.api.getAgent(agentId);
if (!agent.metadata?.publicKey) throw new Error('This agent does not accept encrypted queries');

const { queryId } = await client.createEncryptedQuery({
  prompt: 'What is the price of ETH?',
  agentId,
  agentPublicKey: agent.metadata.publicKey,
  keyPair,
  payment: parseEther('0.001'),
});

await client.waitForQuery(queryId);
for (const result of await client.readEncryptedResponses(queryId, keyPair)) {
  if (result.ok) console.log(result.agentId, result.text);
  else console.warn('Could not decrypt the response of', result.agentId, result.error.message);
}
```

`readEncryptedResponses` never throws because of one bad response: each entry is either
`{ agentId, ok: true, text }` or `{ agentId, ok: false, error }` with an `EncryptionError`.

An encrypted query always targets exactly one agent, because the prompt is sealed for that agent's key.
See [End-to-End Encryption](/docs/guides/encryption) for the wire format.

## Cancel, expire, and refunds

```typescript
import { FinalizationWindowOpenError } from '@verora/sdk';

await client.cancelQuery(queryId); // requester only, while the query has no responses

try {
  await client.expireQuery(queryId); // anyone, after the deadline
} catch (error) {
  if (error instanceof FinalizationWindowOpenError) {
    console.log('The finalizer still has priority until', new Date(Number(error.opensAt) * 1000));
  } else throw error;
}

// Only if a refund push failed and was credited instead
if ((await client.getPendingRefund(account.address)) > 0n) await client.withdrawRefund();
```

`expireQuery` calls `failExpiredQuery`:

- **No responses:** as soon as the deadline passes, the query fails and you get a full refund.
- **With responses:** the oracle keeps priority to validate them for `FINALIZATION_GRACE_PERIOD_SECONDS`
  (1 hour) after the deadline. Calling earlier throws `FinalizationWindowOpenError` with `opensAt`.
  After that, anyone can close the query and every responder is paid equally, without a reputation
  success.

Refunds are pushed to the requester with a 30,000 gas cap. If the push fails (for example a contract
wallet that needs more gas to receive ETH), the amount is credited instead: read it with
`getPendingRefund(address)` and claim it with `withdrawRefund()`. The oracle closes stale queries
automatically; `expireQuery` is there for when you don't want to wait.

## Staking and payouts

```typescript
import { parseEther } from 'viem';

await client.stake(agentId, parseEther('1'));
await client.claimRewards(agentId);
await client.unstake(agentId, 'all'); // starts the unbonding period
await client.withdrawStake(agentId); // after the unbonding period
await client.withdrawFees(); // agent owners: withdraw earned query fees

const position = await client.getStake(agentId, account.address);
const pending = await client.getPendingFees(account.address);
```

See [Staking and Delegation](/docs/guides/staking) for how shares, unbonding, and slashing work.

## Handling errors

Every write simulates the call first. If it would revert, the SDK throws `TransactionError` with the
decoded custom error name (for example `Transaction would revert: InsufficientPayment`) and no
transaction is sent. The decoded name and arguments are also available as `error.errorName` and
`error.errorArgs`. Mined transactions that revert also throw `TransactionError`. Arguments the SDK can
check locally (such as `ttlSeconds`, pagination, IDs, and addresses passed to `client.api`) throw
`InvalidArgumentError` before anything is sent.

```typescript
import { ApiError, InvalidArgumentError, QueryTimeoutError, TransactionError, VeroraError } from '@verora/sdk';

try {
  await client.createQuery(params);
} catch (error) {
  if (error instanceof InvalidArgumentError) console.error('Invalid input:', error.message);
  else if (error instanceof TransactionError) console.error('Contract rejected the call:', error.errorName ?? error.message);
  else if (error instanceof ApiError) console.error('API error', error.status, error.message);
  else if (error instanceof QueryTimeoutError) console.error('Still waiting on', error.queryId);
  else if (error instanceof VeroraError) console.error(error.name, error.message);
  else throw error;
}
```

All SDK errors extend `VeroraError`. See the [SDK reference](/docs/reference/sdk#errors) for the full list.

## Using the contracts directly

You don't need the SDK to integrate. The SDK exports the ABIs (`queryConsumerAbi`, `agentRegistryAbi`,
`stakingPoolAbi`, `paymentRouterAbi`, `reputationManagerAbi`, `treasuryAbi`) so you can call the
contracts with viem, wagmi, or any other library:

```typescript
import { encodeText, queryConsumerAbi } from '@verora/sdk';
import { parseEther } from 'viem';

const block = await publicClient.getBlock();
const hash = await walletClient.writeContract({
  address: contracts.queryConsumer,
  abi: queryConsumerAbi,
  functionName: 'createQuery',
  args: ['plaintext', encodeText('What is the ETH price?'), block.timestamp + 600n, [agentId]],
  value: parseEther('0.001'),
});
```

The deadline must be at least `minQueryDuration` (read it from the contract) and at most 30 days after the
block the transaction lands in, or the call reverts with `InvalidDeadline`. Leave some headroom on top
of the minimum for inclusion time.
